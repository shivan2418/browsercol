# Each visual pattern is one component with its styles beside it; themes speak only through tokens

Almost all of the Browser UI's CSS was one 3,600-line `<style>` block in `ui/index.html`, far from the components in `ui/src/`. Repeated patterns were half made into components: `Box` (`frame.tsx`) existed while six places wrote its markup by hand, and panels patched a shared rule from outside (`.europe .box`, `.options .box`, `.colony .goods`), so a bug in the base rule could not be fixed in one place. This extends ADR 0004 (colours from tokens) and ADR 0006 (native controls styled in CSS) with how the styles are laid out, and keeps the owner's condition: a theme restyles the whole UI from one place, never by editing each component (#421).

- **One component per visual pattern.** A boxed section, a goods icon with its amount, a window frame, a button: each is drawn by one component. A variant is a prop of that component (WindowFrame's `advisor` sets `data-advised`), never a panel's selector reaching into it (`.europe .box`).
- **Styles beside their component.** A component's rules are in a `.css` file next to it, imported by the component (`import './window-frame.css'` in `frame.tsx`); Vite bundles them. No new styling system: no Tailwind (ADR 0006), no CSS-in-JS. What stays in `index.html` is the page shell (`@layer base`) and the rules not yet moved.
- **Tokens are the only theme interface.** A theme is custom properties on `:root`: the palette's colours (`theme.css`, `:root[data-theme=…]`), the font set (`fonts.css`, `:root[data-fonts=…]`), and the other tokens in `tokens.css`: spacing steps (`--space-1` to `--space-6`), radii (`--radius-s`, `--radius-m`), border widths (`--border`, `--border-thick`), the caption's type (`--caption-size`, `--caption-weight`, `--caption-case`, `--caption-tracking`) and shadows (`--shadow-window`, `--shadow-paper`, `--shadow-popup`). A component never hard-codes a colour, font family, spacing, radius, border width or shadow a theme might change.
- **A component may name its own tokens**, declared on `:root` in its sheet and defaulting to global ones (`--frame-pad: var(--space-5) var(--space-6)`). A theme then changes every window in one rule (`--frame-pad`), or every spacing at once (`--space-5`). A value off the global scale (the advisor paper's margins) may be a literal, but only as such a token's default.
- **Cascade layers**, declared first in `index.html`: `@layer reset, base, components, theme;`. A later layer wins over an earlier one whatever the specificity, so a theme's rules win over a component's without `!important` or a longer selector. The token files are in `theme`; each component's sheet is one `@layer components { … }` block; the page shell in `index.html` is in `base`. `index.html` puts its blocks in their layers by an attribute, `<style data-layer="components">`, which `vite.config.ts` (and Storybook's `main.js`) turn into `@layer` blocks (`scripts/page-styles.ts`): wrapping the long block by hand would re-indent every line of it, and every branch that touches it would conflict.

`theme.test.ts` checks the rules: the layer order comes first; the token files are in `theme`; each component sheet is one `components` block, imported by a component; it takes colours, font families, spacing, radii, borders and shadows from tokens; and it names no panel (`.dialog`, `.colony`, `.europe`, `#preferences`, `[data-kind…]`).

## Moving the rest

The split is done a component at a time, when a panel is touched, never as one rewrite. Rules still in `index.html` are in `@layer components` too, so a moved rule and the rules left behind still meet by specificity, and only their order changes: the component sheets come after `index.html`'s. Before a move, check the ties: a rule left behind with the same specificity that came after the moved one won before and loses after. A moved rule that must lose such a tie is written at no weight with `:where()` (`:where(.frame) { max-height: 100% }`, which `.dialog`'s size must override). Compare the panels' screenshots (below) and, with `--styles`, their computed styles before and after.

`reports.css` is in `@layer components` like the rest. It is the sheet of the reports panels, not of one component, so it names the dialogs it sits in and `theme.test.ts` (`PANEL_SHEETS`) does not hold it to the token and panel-name rules.

## Screenshot comparison

`ui/scripts/looks.ts` (`just browser looks`, part of `just suite`) opens the key panels in a game from a fixed preset (`?preset=diplomacy`, seed 1): the colony panel, Europe, the Continental Congress report, Preferences and a negotiation, in Chromium and Firefox, and compares each with its approved picture in `ui/looks/`. A panel of another size, or with more than 0.05% of its pixels changed past anti-aliasing, fails the run, and its shot and a picture of the changes are left in `.cache/looks/`. The pictures stay steady: one page size, fonts and images loaded, no animation or caret, the pointer away. A change meant to show is approved deliberately: look at the shots, then `just looks-approve` and commit the pictures with the change. With `--theme`, `--fonts` or `--css` the script shoots a theme to look at instead of comparing.

## Considered Options

- **Tailwind or CSS-in-JS:** rejected, as in ADR 0006: a second styling system beside the token CSS, and the tokens would have to be mirrored into its config.
- **CSS Modules (`*.module.css`):** not now. Scoped class names would stop a panel's selector reaching into a component, but the tests and the browser scripts find elements by these class names, and the token check works as well on plain sheets. The rule against panel selectors in component sheets does the same job for now.
- **Leaving the rules not yet moved unlayered:** rejected. Unlayered rules beat every layer, so every moved rule would lose to every rule left behind whatever its specificity: moving the window frame alone made its close button take the button bevel back.
- **Re-indenting `index.html` inside `@layer` by hand:** rejected for the conflicts it would give every open branch; the `data-layer` attribute does it at build time instead.
- **Specificity (`.theme-dark .frame`) or `!important` for themes:** rejected; a theme would have to out-weigh each component's selectors one by one.

## Consequences

- A new component with a visual pattern gets its own sheet beside it, in `@layer components`, using tokens; a theme never needs a component edited.
- A new theme is a block of token values (`:root[data-theme='NAME']`, `:root[data-fonts='NAME']`), and may set any global or component token there.
- A class says what an element is (`box`, `frame`, `pic`); its state or variant is an attribute. A state with an ARIA attribute uses that (`aria-selected`, `aria-pressed`). A yes-or-no state is a `data-*` flag, present or left out, written with `flag()` (`flag.ts`) and matched by `[data-x]`: React writes a boolean as the text "true" or "false", and `[data-x]` matches both. A state with more values names its value (`data-sign="loss"`, `data-spaced="wide"`). Joining a component's own class with a caller's is `clsx` (`clsx('box', className)`).
- What is selected (an item picked in a list, tree or grid) and what is pressed (a toggle button that is on) have one look each, in `selection.css`, keyed on `aria-selected`, `aria-current`, `aria-pressed` (and `data-selected` where no ARIA attribute fits) and drawn by `--selected-bg` and `--pressed-bg`: a tint over the item's own background, the same for both by default. A panel never styles its own pick; `theme.test.ts` checks it (#437).
- The patterns found in `index.html` are moved a pattern at a time (#435): the box (`Box`, `box.css`), quiet text, headings (`Heading`), button rows (`ButtonRow`), pictures (`Pic`), tooltips, the option editor, the modifiers and rules-help tables, the start window, form controls and buttons with tabs (`button.css`, whose flat variant is the `data-flat` attribute). Each has its sheet beside its component, and `theme.test.ts` (`MOVED`) fails if a rule for one comes back to `index.html`. The three unit chips are now three components, named by what they are (`PlanPills` in `plan-pills.css`, `EuropeEntry` in `europe-entry.css`, the colony's occupation badge in `occupation-badge.css`), and a goods amount is always its icon and number, laid out by `GoodsAmount` (`goods.css`): a list of them lays itself out (Europe's `market-goods`, the warehouse's line), and no panel's rule patches it (#449). Selectable rows stay as they are, each with its own spacing and layout; only their selected look is shared (`selection.css`). Left: the reports' tables, which differ in padding, cell lines and alignment. The buttons stay in the components layer: moving them to base waits for `.ui-select` and `.ui-number-step` to carry their own hover.
